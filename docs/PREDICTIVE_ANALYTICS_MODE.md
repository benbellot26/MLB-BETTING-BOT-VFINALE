# Predictive Analytics Mode

## Objective

The production bot is an MLB probability engine first and a betting selector second.

The primary objective is to make announced probabilities as close as possible to the true long-run frequency of the modeled event. A single loss does not invalidate a 65% forecast; calibration is evaluated across many comparable forecasts.

Primary validation metrics:

- Brier score: lower is better.
- LogLoss: lower is better and strongly penalizes unjustified confidence.
- Calibration / ECE: predicted probability bands should match observed frequencies.
- Point-in-time integrity: only information available at the forecast timestamp may be used.

Economic metrics such as executable-price EV, CLV and realized P/L remain useful secondary diagnostics, but they must not be allowed to contaminate the baseball probability itself.

## Probability products

Every analyzed market should preserve separate probability products:

1. `p_baseball_raw`: baseball-only probability before empirical calibration.
2. `p_baseball_calibrated`: baseball-only probability after the current calibration layer.
3. `p_market`: de-vigged sharp-market benchmark.
4. `p_posterior`: market-aware ensemble candidate. This is shadow-only until validated.
5. `p_predictive_final`: probability shown as the primary predictive output.

For the current V13.5.2 generation, `p_predictive_final` remains equal to `p_baseball_calibrated`. This is intentional. The market-aware posterior is not promoted from a small sample.

## Historical evidence hierarchy

Historical games are useful only when their evidence role is explicit.

### Tier A — native current-generation observations

A genuine V13.5.2 pregame observation produced live, carrying the exact current predictive contract and later settled from the final result. This is the strongest evidence.

### Tier B — exact archived pregame replay

A durable source replay may count toward current baseball calibration when the archived HTTP sources reconstruct the exact pregame information state and the row carries the current predictive contract. The probability used for calibration is **not** the current layered replay output. The backfill persists a pre-candidate run/distribution baseline and reconstructs `p_replay_baseline_raw` from that frozen baseline. This prevents historical candidate layers from grading themselves on probabilities they helped create.

If the replay also contains a valid historical sharp-market snapshot, it may contribute to posterior validation. Posterior evidence is generated by blocked chronological walk-forward: all phases of one game stay inside the same holdout block, calibration for that block is fitted only from strictly earlier games, and missing historical market probabilities are never fabricated.

### Tier C — broad 2026 walk-forward reconstruction

The existing 2026 dataset contains 1,801 historical games and is valuable for large-sample research, ablations, structural comparisons and calibration-shape diagnostics. It remains research-only for the current native calibration because it does not contain the exact current V13 feature and market snapshot for every game. In particular, historical odds, Statcast and historical forecast weather are not fabricated.

### Tier D — probabilities from older bot versions

Old V9/V10/V12/V13 probabilities are benchmarks only. They can show whether the current system improves Brier, LogLoss or calibration, but they are not relabeled as V13.5.2 observations.

Native evidence overrides replay evidence when the same `game_pk + phase` exists in both sources, so the same game cannot inflate calibration volume.

## Posterior promotion rule

Posterior promotion evidence is cumulative rather than daily. For each market, the system combines:

- exact-replay blocked walk-forward observations with a recorded historical sharp probability; and
- genuine current-generation live observations.

The merge key is `game_pk + phase + market`, and a genuine live current-generation observation replaces a historical replay collision.

A posterior may only become a promotion candidate after at least 300 paired, deduplicated observations for the evaluated market cohort and only when both conditions hold:

- Brier improvement versus calibrated baseball is at least 0.001.
- LogLoss improvement versus calibrated baseball is at least 0.002.

The 1,801-game legacy 2026 reconstruction does **not** count toward this 300-pair posterior threshold unless an exact archived pregame market snapshot exists for the game. It can still guide baseball-model research and ablations.

These thresholds identify a candidate for review; they do not silently switch production probability. Any promotion must preserve point-in-time integrity and be validated across phases/markets so a local short-term improvement does not create a global regression.

## Calibration volume

Exact Tier-B replay baselines can now contribute to the baseball calibration sample floors alongside Tier-A native observations. Current strict activation floors remain unchanged:

- global diagnostic cohort: 600;
- market cohort: 400;
- phase-market cohort: 300.

The calibration fitter still uses expanding walk-forward method selection plus an untouched chronological final holdout. Adding historical replay volume therefore does not remove the out-of-sample activation requirement.

## Discord output

The main game message is analytics-first. It shows the primary probability, uncertainty interval, raw/calibrated baseball probability, sharp benchmark, posterior shadow candidate, calibration status, model-data quality, and available price context.

Ranking and betting-plan Discord cards are intentionally suppressed in predictive analytics mode. The user remains responsible for interpreting the probabilities and deciding whether a quoted price creates a sufficiently attractive opportunity.

The predictive post-mortem reports the cumulative posterior evidence count split between exact historical out-of-sample observations and current-generation live observations, together with paired Brier and LogLoss improvement.

## Profitability

Accurate probabilities are necessary but do not guarantee profitability. Long-run profitability also requires obtaining prices whose implied break-even probability is below the true event probability, while accounting for uncertainty, limits, execution quality and variance.
